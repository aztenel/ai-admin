## Запуск

```bash
cd apps/pult && npm install
npm run dev        # демо-данные, без сервера: http://localhost:5173/
npm run dev:live   # настоящий код бота на заглушках: http://127.0.0.1:5174/app/?c=winchester (база клиентов, номер бота без рассылок) и ?c=dent; владелец owner-key-123456, сотрудник Winchester staff-key-winch-0001
npm run build      # проверка типов + сборка в dist/ (в git не попадает)
npm run embed      # сборка + копия для сайта: pult-app.gen.js в корне (то же, что npm run build:app в корне)
npm run shots -- <папка>   # снимки всех размеров (при запущенном npm run dev)
npm run e2e:campaigns -- <папка>   # проверка раздела «Рассылки» в браузере: сам поднимает dev:live на свободном порту (и собирает пульт во временную папку — проверка без связи), снимки — в папку
npm run e2e:contacts -- <папка> [--demo]   # раздел «Клиенты»: без --demo — dev:live с базой D1 в памяти (Node 22+), с --demo — демо-данные пульта без бота
```

## Откуда данные

- **Рабочий режим** (по умолчанию): тот же API, что у рабочего пульта, — `/api/inbox/me|list|chat|send|act|media|leads`, `/api/bc/list` (телефоны и состояние номеров, рассылки), `/api/studio/list` (компании владельца). Раздел «Клиенты» (`src/screens/Clients.tsx` + `src/clients/`, грузится при первом открытии) — `/api/contacts/status|segments|list|card|add|consent|restrict|lift|review|import|import/confirm|import/discard|sync|probe|stops` (`src/data/live-contacts.ts`; понятия — `src/model/contacts.ts`): единая база контактов в D1 (журнал Altegio, импорт, ручное добавление), согласия и запреты с историей; номера в списке и предпросмотре импорта — маской, полностью — только в карточке одного клиента; нет базы D1 (боевой сайт до решения владельца) — экран с причиной, без запросов, которые ответили бы 503. Раздел «Рассылки» (`src/screens/Campaigns.tsx` + `src/campaigns/`, грузится при первом открытии раздела) — `/api/bc/list|get|check|create|test|act|tick|auto|service` и `/api/crm/segments|list|refresh` (`src/data/live-campaigns.ts`; понятия — `src/model/campaigns.ts`). Решение владельца 19.10.2026: две вкладки — «Маркетинг · основной номер» (шаблоны Meta: обзор номера, база клиентов и сегменты, автосценарий «Пора на стрижку», история, мастер — только основной номер) и «Сервисные · номер бота» (что бот шлёт сам: напоминания и просьба об отзыве; ближайшие в очереди — номера маской, сколько ушло за 3 дня; только смотреть — владельцу и сотруднику одинаково). Рассылок текстом с номера бота пульт не создаёт; старая страница `/broadcast` пультом не используется. Права и арендатора проверяет сервер; параметр `c=` — только выбор среди разрешённых. Сервер не ответил — пульт пишет, что случилось; демо вместо настоящих данных не подставляется.
- **Демо** — только явно: сборка с `VITE_PULT_DATA=demo`, адрес `/demo…` или `?demo`. Три вымышленные компании (`src/data/demo.ts`, рассылки и база — `demo-campaigns.ts`, раздел «Клиенты» — `demo-contacts.ts`: у барбершопа — 60 клиентов из «Altegio» на «черновике» с тестовыми клиентами, у сервис-центра — без Altegio, у компании без чатов — базы нет): барбершоп с двумя номерами (основной — Meta, с базой клиентов; номер бота — Green-API, без рассылок), сервис-центр с двумя филиалами (без базы, сигнал Meta), новая компания без чатов. `?staff` в адресе — вид сотрудника. Пометка «демо» рядом с названием, звонки не набираются. В рабочем режиме файл демо не загружается.

## Как устроено

- `src/model/` — понятия: компания → (филиалы) → каналы (номера) → чаты → сообщения. Канал (через какой номер) и режим (бот, человек, просьба) — разные вещи.
- `src/data/live.ts` — перевод ответов сервера в эти понятия; `demo.ts` — демо с тем же интерфейсом; `read-marks.ts` — «прочитано» на этом устройстве.
- `src/state/store.ts` — состояние, опрос раз в 15 с (свёрнутая вкладка не опрашивает), мгновенная отправка с «Повторить» при ошибке.
- `src/inbox/` — чаты: список, выбор номера/филиала, переписка, просьбы клиента, поле ответа, карточка клиента.
- `src/screens/` — заявки, рассылки, клиенты, настройки (грузятся при первом открытии); `src/clients/` — карточка клиента, добавление, импорт, панель синхронизации.
- `src/shell/` — полоса разделов (планшет, компьютер), вкладки снизу (телефон), компания.
- `src/index.css` — цвета и шрифт. Палитра Tailwind по умолчанию отключена: в компонентах только токены (`bg-surface`, `text-fg-2`…).

**Раскладка.** Телефон (< 768): список → переписка → карточка клиента, по одному экрану, «назад» — жестом или кнопкой; список не выгружается, прокрутка сохраняется. Планшет и ноутбук (768–1279): список + переписка, карточка выезжает справа. Компьютер (≥ 1280): три колонки, карточку можно скрыть — выбор запоминается.

**iPhone.** `viewport-fit=cover`, отступы `env(safe-area-inset-*)`, высота `100dvh`; при открытой клавиатуре корень пульта повторяет `visualViewport` (тот же приём, что в рабочем пульте), поле ответа остаётся над клавиатурой, нижние вкладки прячутся (`.hide-kb` в `index.css`) — иначе под поля оставалось ~250 px. Поля ввода — 16 px (без увеличения страницы), кнопки — от 44 px. Размер шрифта следует «Размеру текста» iOS.

**Вид** — арт-дирекция «тихий инструмент» (третий проход 18.10.2026; синий вместо шафрана — решение владельца того же дня). Холодная нейтральная основа и три ступени поверхностей: полотно `#F2F4F7`, белые панели, заливка `#EEF1F5`. Текст `#11161D` / `#4A5363` / `#616A7A`. Иерархию строят размер, вес и отступы, а не цвет. Синий `#1D5FD0` — одна насыщенная роль (главное действие, отправка, сообщения человека, фокус) и одна бледная (выбранное). Красный — только ошибка, необратимое действие и клиент, который ждёт человека; зелёный — подключено, выполнено. Тёмная тема — графит (`#16191E`, `#0F1114`) и синий `#2F6BE0`, не чёрная. Контраст текста проверен расчётом: подписи ≥ 4.5:1 на всех фонах обеих тем. Палитра и шкала шрифта — `src/index.css`.

- **Список.** Название компании — крупный заголовок; справа капсула «Все номера» (выбран один номер — капсула синяя). В демо над названием строка «Демо · данные вымышленные». Фильтры — вкладки с синей чертой; число ждущих — красное. Строка чата всегда в три строки одной высоты: кто и когда; последнее сообщение; одной фразой — кто ведёт и через какой номер («Просит человека · ИИ-администратор», «Человек · Основной WhatsApp»; обычное «ведёт бот» — только значком). Клиент ждёт — вместо времени сообщения красным «сколько ждёт».
- **Переписка.** В шапке — номер, через который идёт чат; карточку клиента открывает нажатие на имя. Под именем, в самой шапке, — плашка с главным действием: розовая «Просит человека · ждёт 9 мин — Взять чат», серая «Ведёте вы · бот молчит до … — Вернуть бота». На телефоне у «назад» — сколько ещё чатов ждут человека. Просьба клиента — карточкой-задачей над полем ответа. Над полем, по линии текста, мелко: с какого номера уйдёт ответ.
- **Пузыри — три голоса, три веса:** клиент — нейтральный серый, бот — бледно-синий, человек — сплошной синий (это сказали вы). Подпись «Бот» / «Оператор» / «Оператор, с телефона» со значком — только когда отвечающий сменился. Время — мелко внутри пузыря.
- Карточка клиента — подпись над значением, как в «Контактах» iPhone; настройки и заявки — сгруппированные списки на полотне, значки в плитках.
- Скругления по ступеням: 10 px — кнопки, поля и плитки, 12–16 px — плашки, группы и карточки, 18–20 px — пузыри, поле ответа и листы. Значки Lucide 20 px в навигации, 16 px в тексте. Системный шрифт (San Francisco на iPhone и Mac).
- Вырезы экрана — через переменные `--safe-t/-b/-l/-r` (`src/index.css`): так снимки проверки изображают iPhone с вырезом и «полоской Домой».

## Два номера одной компании

- У компании может быть номер Meta Cloud API (`wa`) и номер Green-API (`ga`), плюс чат на сайте. Справа от названия компании — выбор: «Все номера» или один номер (с филиалами — «Все филиалы» → филиал → номер). Число ждущих ответа — у каждого пункта.
- В строке чата — номер, на который написал клиент; над полем ответа — «С номера …». Сервер отвечает с того же номера (`/api/inbox/send` по `ch` чата).
- Клиент, писавший на оба номера, — две переписки одного контакта (контакт — по номеру телефона). В карточке клиента — «Писал и на другой номер» с переходом. Переписки не сливаются и не переносятся между номерами.
- Телефон и состояние номеров — из `/api/bc/list` (Meta: `display_phone_number`, Green-API: `wid`).

## Чего нет на сервере (и что нужно сделать)

1. **Названия номеров** («ИИ-администратор», «Основной WhatsApp»). Сейчас показываем телефон и вид подключения. Наименьший путь: два поля паспорта (`waLabel`, `gaLabel`) в `/studio` + поле `channels` в ответе `/api/inbox/list` (`[{ ch, name, phone }]`); после фазы 2 — колонка `channels.label`.
2. **Бот только на одном номере.** Сейчас бот отвечает на обоих номерах (пока человек не ответил — тогда пауза 2 ч). Если основной номер должен быть «только люди», нужна настройка на канал и проверка в `handleGreen`/`handleWAText` до вызова бота — это правка логики бота, нужна отдельная задача и тесты.
3. **Филиалы** — в сервере их нет (одна локация Altegio на компанию). Пульт показывает выбор филиала, только если сервер вернёт филиалы; сейчас — только в демо.
4. **Непрочитанные** — счётчика на сервере нет (цель — `chats.unread_count`). Пока «новое» = сообщение клиента после последнего открытия чата **на этом устройстве**.
5. **Назначенный оператор**, статусы доставки, отправка файлов, фото профиля — в API нет; в пульте не показываются.
6. **Раздача с Workers Static Assets** (фаза 3–4): пока не нужна — пульт раздаёт сам Worker из `pult-app.gen.js` (см. «Раздача с сайта»). Нет манифеста и значков для экрана «Домой» у `/app/` — на iPhone ставится как обычная закладка.
7. **Рассылки:** нет шаблонов из Meta со статусом (название шаблона вписывают руками), стоп-листа списком (только число «отказались»), «доставлено / прочитано», «записались за 7 дней», отложенного запуска, «Пауза всего» и расхода за месяц — в пульте их нет. Стоимость — оценка: получатели × 27,3 ₸ (`MARKETING_PRICE_KZT`, цена шаблона Marketing с экрана Wazzapo 19.10.2026). Права: сервер разрешает сотруднику создавать и запускать рассылки (ТЗ — «администраторы только смотрят»); не разрешает «Обновить базу», настройки автосценария и «Снять сигнал Meta» — этих кнопок у сотрудника нет. Запуск при сигнале Meta снимает сигнал для всего номера — поэтому при сигнале сотруднику сервер отвечает 403 «может только владелец», а владельцу задаёт вопрос, где это сказано («Всё равно продолжить» — только у владельца).
8. **Вкладка «Сервисные»** (`src/campaigns/ServiceMessages.tsx`) показывает только то, что отдаёт `GET /api/bc/service`: виды и включены ли (без записи через Altegio — выключены все: бот строит напоминания только по своим записям в Altegio, `altegio: false`), до 50 ближайших в очереди — только то, что бот отправит (отменённую и перенесённую запись, просьбу по ней и «стоп» сервер убирает тем же правилом, что и при отправке, `remindLive`), сколько ушло за 3 дня (только удачные отправки — отметки `rmok:`). Кто шлёт — «с того номера, куда писал клиент»; про боевой сайт и черновик — только владельцу. Дошло ли сообщение, ответил ли клиент, оставил ли отзыв — на сервере нет. Менять здесь нечего: напоминания и ссылку на отзывы задают в настройках бота. Отправляет фоновая задача боевого сайта (раз в минуту); у черновика её нет. У Winchester с 30.10.2026 (`journal: true`) — режим без бота: напоминания и отзыв по всем записям журнала Altegio со второго номера (`services/reminders/journal.js`), заголовок «Что уходит само», предупреждения «бот выключен» нет, пауза номера после отказа Green-API (`hold`) — плашкой «Отправка на паузе».

## Раздача с сайта (`/app/`, 19.10.2026)

- **Как попадает на сайт.** `npm run embed` здесь (или `npm run build:app` в корне; `tools/build-pult-app.mjs`) — проверка типов и сборка Vite, затем все файлы `dist/` кладутся в один модуль `pult-app.gen.js` в корне репозитория (как старый пульт в `pult.gen.js`; руками не править). `worker.js` передаёт его в `createWorker`, раздаёт `src/controllers/pult.js` (`pultApp`). Workers Static Assets и `wrangler.jsonc` не нужны. Попадает на черновик после коммита в `dev` (Cloudflare выкладывает сам), на боевой — только по слову владельца.
- **Правили пульт — пересоберите копию**, иначе на сайте останется старая версия: `npm run embed`, затем в корне `npm test`. Свежая ли копия — `npm run check:app` в корне (сверяет отпечаток исходников `src/`, `index.html`, `vite.config.ts`, `tsconfig.json`, `package-lock.json`; Vite не нужен). Сборка воспроизводима: те же исходники — тот же файл.
- **Адреса:** `/app` → `/app/` (301, параметры сохраняются); `/app/` и `/app/index.html` — страница; `/app/assets/*` — файлы сборки; остальное — 404 (адреса внутри пульта — после `#`). Вход: нет входа — `/api/*` отвечает 401, пульт ведёт на `/login?next=/app/…`, после входа — обратно в пульт (владелец и сотрудник). Сами файлы отдаются без входа и без чтения хранилища: данных в них нет.
- **Заголовки:** страница — как остальные (`page()`: без кэша, без встраивания, `nosniff`, CSP `default-src 'self'`); встроенный скрипт темы в `index.html` разрешён по хэшу (`script-src 'self' 'sha256-…'`, хэш считает сборка), стили — `'self' 'unsafe-inline'` (Radix вставляет `<style>`). Файлы `assets/` — `public, max-age=31536000, immutable` (в имени хэш содержимого). Поэтому `base: "./"` в `vite.config.ts` не менять: сборка с адресами от корня сайта под `/app/` не найдёт свои файлы (сборка откажется).
- **Размер:** копия ≈ 690 КБ (≈ 209 КБ в сжатом виде), весь Worker с ней — ≈ 2,4 МБ / 576 КБ сжатый (`wrangler deploy --dry-run`; предел — 3 МБ сжатого на бесплатном тарифе, 10 МБ на платном). Сборка откажется, если копия больше 2 МБ.
- **Проверено:** на заглушках — `test/unit/pult-app.test.mjs` (заголовки, хэш скрипта, все подгружаемые части есть, 404, вход с возвратом), маршруты `/app…` в `test/contract/`; в браузере (Playwright, страница от самого Worker, не Vite) — вход владельца и сотрудника с возвратом в `/app/`, тема, раздел «Рассылки» и мастер подгружаются, нарушений CSP и ошибок консоли нет. **Вживую на черновике не проверено.**
- После выкладки у уже открытого пульта файлы прежней сборки пропадают: раздел, который ещё не открывали, не подгрузится. Тогда пульт сам один раз перезагружает страницу (`vite:preloadError` в `src/main.tsx`; повторно — не раньше чем через минуту, без круга). Если связи нет, страницу не перезагружаем (иначе осталась бы страница браузера «нет интернета», а в приложении с экрана «Домой» нет кнопки «обновить»): раздел или мастер показывает «не загрузился» и «Повторить» (`src/components/boundary.tsx`).

## Решения

- Стек не меняли: React 19 + Vite + Tailwind 4 не мешают ни PWA на iPhone, ни Tauri, ни будущему Capacitor; адреса внутри пульта — после `#`, сборка с `base: "./"` открывается с любого пути.
- Убраны: доска «канбан», графики выручки (Recharts), «Записи» и «Клиенты» на вымышленных цифрах (на сервере для них нет данных; «Клиенты» вернулись 31.10.2026 — на настоящем API базы контактов в D1), анимации `motion`, библиотека значков Tabler, шрифт Inter, компоненты 21st.dev. JS при первом открытии — ≈ 142 КБ gzip (было 175, бюджет 150); раздел «Рассылки» грузится отдельно (≈ 26 КБ, мастер ещё ≈ 14 КБ, API ≈ 2 КБ).
