# Сценарии независимых проверок

Здесь лежат скрипты, которые писали независимые проверяющие (третья и четвёртая проверка кода), чтобы повторить найденные ошибки.
Сеть не нужна: KV, Gemini, Telegram, Meta и Altegio подменены заглушками.

В `npm test` эти сценарии не входят: их около 130 и идут они примерно две минуты. Запускай их перед выкладкой, если менялась запись в Altegio, разбор ответа ИИ или защита ответа.

```
node test/review/run.mjs            # все сценарии
node test/review/run.mjs 4a/t35     # только те, в имени которых есть «4a/t35»
node test/review/run.mjs --save     # запомнить текущие числа как известные (known.json)
```

Вывод каждого сценария сохраняется в `test/review/out/` (в git не попадает).

## Как читать результат

Сценарии печатают пометки: `[ДЕФЕКТ]`, `[НАРУШЕНИЕ]`, `WRONG`, `[ДОШЛО]`. Часть пометок — не ошибки, а осознанные решения или следы того, что ожидание проверяющего устарело. Их числа записаны в `known.json`. `run.mjs` сообщает только о том, чего в `known.json` нет, и тогда завершается с ошибкой.

Известные пометки и почему они остались:

- `3a/s09_limits`, `3a/s10_race` — сценарии ждут прежних лимитов (5 записей на IP) и полной защиты от двух одновременных сообщений одного чата. Лимит на IP сейчас 15; полной защиты от гонки нет (нужен Durable Object).
- `3a/s01`, `3a/s05`, `3a/s08`, `3a/s14` — сценарии ждут прежних текстов («удалите вручную») и повторного уведомления о той же заявке. Сейчас текст другой, а повтор той же просьбы вторую заявку не создаёт.
- `3a/s11_time` — ожидание зависит от шага, который теперь отрабатывает иначе (отмена относится к будущей записи, бот не переспрашивает про прошедшую).
- `4a/t22_callback` — заявка на звонок уходит в браузер только с телефоном; заявка создаётся, когда свободного времени нет, а клиент спрашивает о записи.
- `4a/t23_kvfail` — сценарии ждут ответа «не получилось сохранить заявку», когда не записался общий список. Теперь заявка сохраняется ещё и отдельным ключом, поэтому клиенту честно отвечают «передала».
- `4a/t29_guard_misc` — седьмая заявка за пять недель доходит; в списке их меньше, потому что заявки хранятся 30 дней.
- `4a/t35_names` — «Тимур» и «Тимур Ахметов» считаются одним человеком; «Александра» при совпавших дне и времени — тот же Александр.
- `4a/t39_leads_race` — сценарий смотрит общий список напрямую; на странице `/leads` заявки восстанавливаются из отдельных ключей.
- `4a/t45_tg_latency` — сценарий меряет время всей обработки; ответ клиенту в WhatsApp уходит раньше уведомлений.
- `3b/t28_proto`, `3b/t34_leads_kv` — ошибки старой версии 7.3 (с ней сценарии сравнивают новую).
- `4b/a2_base_units`, `4b/e4_crash_fuzz` — сценарии с испорченными данными в хранилище: страница `/leads` при этом падает (в жизни KV значения не портит).

## Если сценарий нашёл новое

Сначала повтори ошибку коротким сценарием в `test/smoke.mjs`, потом исправляй. После исправления запусти `run.mjs` ещё раз; если пометка осознанная — допиши причину сюда и сохрани числа через `--save`.
