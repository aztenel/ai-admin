# 03. Сравнение функций: SFON и кандидаты

Дата: 06.11.2026. Основание — отчёты 01, 02, 05 и `evidence/*.md`.

## 1. Как читать

- **готово** — есть в коде (и, где отмечено в отчёте 05, проверено тестом) и годится для магазина телефонов без переделки ядра;
- **частично** — механизм есть, но не закрывает требование целиком (например, перемещение без шага «принять/отклонить»);
- **доработка** — нужна правка или своё расширение поверх (новое поле, индекс, шаблон);
- **с нуля** — в проекте этого нет;
- **не подтверждено** — нет доказательства ни «за», ни «против» (у SFON — без доступа к аккаунту).

Для SFON «готово» означает «функция видна в интерфейсе и маркетинге»; вживую не проверялась (отчёт 02).
Odoo, Dolibarr, Tryton, OSPOS в матрицу не вошли: их запуск не делался, а статических данных для каждой строки недостаточно (см. `evidence/extra.md`).

Проверено вживую (отчёт 05) у AureusERP, ERPNext v15 и InvenTree: строки 3, 5, 6, 7, 12, 14, 15, 17, 22, 28, 32. Остальное — по коду.

## 3. Объём переиспользуемой бизнес-логики

**Методика.** Каждой строке присвоено число: готово = 1, частично = 0,5, доработка = 0,25, с нуля = 0, не подтверждено = 0 (осторожно). Считаем три показателя:
- **простое покрытие** — среднее по 33 функциям;
- **взвешенное** — с весами 1/2/3;
- **критичное** — только строки веса 3 (единица, IMEI, двойная продажа, POS, мультиарендность).

Это не «процент готовности продукта»: показатель говорит, какая доля **требований** уже закрыта кодом кандидата, но не учитывает стоимость доработки ядра, обучения стеку и сопровождения (это — в отчёте 06).

## 4. Выводы

1. **ERPNext закрывает больше всех (≈71 % взвешенно)** и по покрытию равен SFON. Провалы — двойная продажа через POS (подтверждено тестом), IMEI2, глобальная уникальность IMEI, Казахстан (ККМ, Kaspi, kk), мультиарендность.
2. **InvenTree (≈50 %)** силён ровно в ядре склада (единица, уникальность, распределение под блокировкой), но в нём нет кассы, денег и долгов — это половина продукта магазина.
3. **AureusERP (≈38 %)** широк по модулям, но по критичным строкам набирает только 25 %: целостность IMEI в POS провалена тестами, а исправление — в ядре.
4. **Inventoros (≈44 %)** отпадает по лицензии AGPL, **Bagisto (≈15 %)** — по функциям (это витрина).
5. **Ни у кого нет фискализации РК и Kaspi** — это пишется с нуля при любом выборе.
6. Общие для всех доработки: IMEI2 и проверка IMEI (контрольная цифра Luhn), гарантийный талон по закону РК, казахский язык, Trade-In.
