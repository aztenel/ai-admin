# 06. Решение по архитектуре (ADR)

Дата: 06.11.2026. Статус: **предложено**, ждёт решения владельца.

## 1. Контекст

- Продукт: ERP/POS для независимых магазинов телефонов Казахстана, продаётся по подписке (как SFON, ориентир цены 21–35 тыс. ₸ за 2 магазина — отчёт 02).
- Первый клиент: Prime Mobile (сейчас на SFON).
- Главный риск продукта — **целостность IMEI**: один телефон нельзя продать дважды, ни подряд, ни одновременно с двух касс, ни через API.
- Проверено вживую (отчёт 05): ни один кандидат не закрывает это на всех путях продажи. Лучшая схема защиты — у ERPNext (счёт) и InvenTree (заказ): блокировка строки единицы + проверка «в наличии на этом складе» внутри транзакции.

## 2. Варианты

### A. Форк (или надстройка) полноценной ERP

**A1 — ERPNext + своё приложение Frappe** (лучший из «полных»):
- ➕ Больше всех готовой логики (≈71 % требований взвешенно, отчёт 03): единица, себестоимость единицы, гарантия, бухгалтерия, возвраты, перемещения с транзитом, ревизия, импорт, REST, вебхуки.
- ➕ Кастомизация своим приложением без форка (`hooks.py`, Custom Fields, override классов).
- ➖ Двойная продажа через POS Invoice — **9 из 10** в тесте; нужна своя блокировка или режим кассы через Sales Invoice.
- ➖ Мультиарендность = сайт на клиента (отдельная БД, свои миграции, свои воркеры) — сотни баз при росте.
- ➖ Python/Frappe — отдельная экспертиза; ежегодные мажорные версии меняют модель данных (Serial No уже менялся дважды).
- ➖ Тяжёлая эксплуатация (MariaDB, Redis ×3, воркеры, Node для ассетов), ≈1,5–2 ГБ ОЗУ на сайт под нагрузкой [по опыту, не замерялось].
- ➖ GPL-3 (для SaaS без раздачи копий — допустимо) + обязательный ребрендинг (`TRADEMARK_POLICY.md`).
- ➖ Нет Казахстана (ККМ/ОФД, Kaspi, kk) — писать всё равно.

**A2 — форк AureusERP** (тот же стек Laravel/Filament):
- ➕ MIT, POS, бухгалтерия, закупки, Filament-админка, 1 200+ проходящих тестов склада и POS.
- ➖ Проваленные критичные сценарии (двойная продажа 15/15, продажа несуществующего IMEI, дубли IMEI, минус в остатках) сидят **в ядре** POS и склада (`PickingGenerator::forceComplete`, `ProductQuantity::adjustStock(allowNegative)`). Исправлять = вечный форк проекта, который меняется на 700 коммитов за квартал.
- ➖ Модель Odoo (quant/move/move line/picking) избыточна для розницы телефонов: 405 тыс. строк, которые придётся понимать и сопровождать.
- ➖ Мультикомпания, а не SaaS-изоляция (общие строки `NULL`, консоль без scope, глобальные роли).

### B. Laravel 13 + Filament 5 + готовые библиотеки, своё доменное ядро

Своё компактное ядро под магазин телефонов (единица с IMEI1/IMEI2/SN, движения, касса, деньги, долги, документы), всё остальное — проверенными пакетами:
`filament/filament` (админка), `spatie/laravel-permission` с командами на арендатора, `laravel/sanctum`, `maatwebsite/excel` (импорт/экспорт), `barryvdh/laravel-dompdf` или `spatie/laravel-pdf` (документы с кириллицей), `spatie/laravel-activitylog` (журнал), `milon/barcode`, Horizon (очереди), PostgreSQL 16 (RLS, частичные уникальные индексы, `FOR UPDATE`).
Идеи и куски кода (MIT, с сохранением копирайта) — из AureusERP (нумерация документов `SequenceService`, POS-идемпотентность по `uuid`, Filament-ресурсы, PDF), схема защиты единицы — по образцу ERPNext/InvenTree.
- ➕ Целостность IMEI закладывается в схему БД, а не латается.
- ➕ Мультиарендность «по умолчанию закрыто» (одна БД, `tenant_id` + RLS) — дёшево держать сотни магазинов.
- ➕ Один стек, MIT везде, нет чужого графика выпусков, нет товарных знаков.
- ➕ Простая эксплуатация: PHP-FPM/Octane, PostgreSQL, Redis — доступно у хостингов в Казахстане.
- ➖ Больше своей разработки: MVP ≈ 1 300–1 850 ч против ≈ 800–1 200 ч у A1 (отчёт 07).
- ➖ Бухгалтерия «как в ERP» не нужна в MVP, но позже — либо своя упрощённая, либо выгрузка в 1С.

### C. Готовая ERP для склада + отдельный премиальный storefront

Например, ERPNext/InvenTree для склада + Bagisto для витрины.
- ➕ Витрина Bagisto зрелая (каталог, корзина, ru, KZT).
- ➖ Две системы, два стека, синхронизация остатков и IMEI между ними; у Bagisto нет kk и Kaspi, учёт по единицам на витрине отсутствует.
- ➖ Витрина не главное для магазина телефонов на старте: SFON даёт простую витрину наличия, а главная боль — склад и касса.
- Вывод: витрину делать **позже** и тонко — страницы наличия из своего API (как Open API SFON) или Bagisto как отдельный продукт, если клиенты попросят полноценный интернет-магазин.

## 3. Сравнение по критериям

Оценка 1–5 (5 — лучше).

| Критерий | A1 ERPNext | A2 форк AureusERP | **B Laravel + своё ядро** | C ERP + витрина |
|---|---|---|---|---|
| Скорость MVP для одного магазина | **5** | 3 | 3 | 2 |
| Сложность сопровождения | 2 | 1 | **4** | 1 |
| Обновления upstream | 2 (ломающие мажоры) | 1 (форк) | **5** (только библиотеки) | 2 |
| Безопасность / целостность IMEI | 3 (нужна доработка POS) | 1 | **5** (в схеме БД) | 3 |
| Мультиарендность | 2 (БД на клиента) | 2 | **5** | 2 |
| Масштабирование до сотен магазинов | 2 | 3 | **4** | 2 |
| Стоимость инфраструктуры | 2 | 4 | **4** | 2 |
| Коммерческая лицензия | 3 (GPL + бренд) | 5 (MIT) | **5** (MIT) | 3 |
| Зависимость от поставщика | 3 | 3 | **4** (Filament — ключевая зависимость) | 2 |
| **Сумма** | 24 | 23 | **39** | 19 |

Laravel выбран не по умолчанию: при задаче «только Prime Mobile, один магазин, быстро» выиграл бы A1. Решает требование **продавать многим магазинам по подписке** — там вес сопровождения, изоляции и стоимости инфраструктуры больше скорости первого запуска.

## 4. Решение

**Стратегия B**: Laravel 13 + Filament 5 + PostgreSQL 16 + Redis, своё доменное ядро «единица IMEI», мультиарендность через `tenant_id` + RLS.

- **Лучший проект-основа: AureusERP** — как донор кода и решений (MIT, тот же стек), **не как форк**: забираем подходы POS-идемпотентности, нумерации документов, структуры Filament-ресурсов, печатных форм; ядро склада и кассы — своё.
- **Второй вариант: ERPNext v16 + своё приложение Frappe** — если владелец решит сначала запустить только Prime Mobile как можно быстрее и согласится на Python/Frappe и GPL. Условия: своя блокировка в POS (или касса через Sales Invoice), Custom Field IMEI2 + уникальные индексы, казахские печатные формы, план перехода на мультисайт.
- **Эталон модели данных и API склада: InvenTree** (MIT) — схема уникальности и блокировок, REST/OpenAPI.

### Архитектура (кратко)

```
Касса (PWA, офлайн-очередь с Idempotency-Key, камера-сканер)
Админка (Filament 5)                 Публичный API (Sanctum, OpenAPI), вебхуки
        └──────────────┬──────────────────────┘
               Laravel 13 (модульный монолит)
  Модули: Tenancy · Catalog · Devices(IMEI) · Stock · Purchasing · Sales/POS
          · Returns/TradeIn · Transfers · Stocktake · Cash&Debts · Documents
          · Reports · Import · Integrations(ОФД, Kaspi) · Billing
               PostgreSQL 16 (RLS, FOR UPDATE, частичные UNIQUE, CHECK)
               Redis (очереди Horizon, кэш, блокировки)  ·  S3-хранилище (PDF, фото)
```

Правила: одна функция продажи единицы для всех каналов; журнал движений только на добавление; деньги — в целых тиынах (bigint); время — UTC в базе, Asia/Almaty в интерфейсе; каждый модуль — свои таблицы и сервисы, контроллеры тонкие.

### Инфраструктура

- Хостинг — **в Казахстане** (локализация персональных данных граждан РК): VPS/облако казахстанского провайдера.
- Старт (до ~50 магазинов): 1 сервер приложения 4 vCPU / 8 ГБ, управляемый PostgreSQL или отдельная ВМ 2–4 vCPU / 8 ГБ с репликой и PITR, объектное хранилище, Redis. Цены нужно запросить у провайдеров — здесь не приводятся, чтобы не выдумывать.
- Рост: горизонтально — несколько серверов приложения за балансировщиком, реплика чтения для отчётов.

## 5. Риски решения

| Риск | Мера |
|---|---|
| Больше своей разработки, чем у A1 | Жёсткий объём MVP (отчёт 07), паритет с SFON только по тому, чем Prime Mobile реально пользуется (выяснить на демо его аккаунта) |
| Filament 5 — молодой мажор | Бизнес-логика в сервисах, не в Filament; Filament только как UI |
| Ошибки в своём ядре склада | Ограничения в БД + тесты конкурентности в CI + свойства-инварианты (property-based) |
| Фискализация | Интеграция через API сертифицированного ОФД-оператора/онлайн-кассы, а не своя ККМ |
