# 07. План разработки и итоговое заключение

Дата: 06.11.2026. Стратегия — B из отчёта 06 (Laravel 13 + Filament 5 + PostgreSQL 16, своё ядро IMEI).

## 1. Итог в десяти пунктах

1. **Лучшая основа:** стратегия B — своё ядро на Laravel/Filament/PostgreSQL; **AureusERP** (MIT) — донор кода и решений, не форк.
2. **Второй вариант:** **ERPNext v16 + своё приложение Frappe** — быстрее для одного Prime Mobile, хуже для SaaS (БД на клиента, GPL, Python, двойная продажа через POS 9/10 в тесте).
3. **Без изменений берём** (библиотеки и готовые модули): Laravel, Filament, spatie/laravel-permission, Sanctum, laravel-excel, PDF-движок, activitylog, Horizon, milon/barcode; из AureusERP по образцу — `SequenceService` (нумерация под блокировкой), POS-идемпотентность по `uuid`.
4. **Адаптируем** (взять идею/код и переделать под арендатора и IMEI): Filament-ресурсы товаров, контрагентов, POS-экран и кассовые смены AureusERP; печатные формы; схему уникальности и блокировок InvenTree/ERPNext.
5. **Пишем отдельно**: единица IMEI и её журнал, продажа под блокировкой, приёмка партии со сканом, перемещения с приёмом/отказом, ревизия сканом, Trade-In, кассы и долги, гарантийный талон РК, мультиарендность с RLS, фискализация, Kaspi, импорт из SFON, биллинг подписки.
6. **Трудозатраты MVP:** 1 300–1 850 ч (таблица ниже).
7. **Сроки:** MVP у Prime Mobile — **5–7 месяцев** командой 2 разработчика + 0,5 QA; production для сторонних магазинов (фискализация, биллинг, kk, Kaspi, укрепление) — ещё **3–4 месяца**, итого **9–11 месяцев**.
8. **Главные риски:** фискализация и Kaspi зависят от внешних договоров; перенос из SFON без IMEI в API; конкурировать с SFON по цене; объём своей разработки (отчёт 06 §5, ниже §5).
9. **Переход с SFON** — выгрузки Excel + сплошная ревизия сканом + параллельная работа 2 недели (§4).
10. **Первые 10 задач** — §6.

## 4. План перехода Prime Mobile с SFON

Ограничение: Open API SFON отдаёт только товары в наличии без IMEI и себестоимости (отчёт 02) — **перенести всё автоматически нельзя**.

1. **Инвентаризация данных** (этап 0): с владельцем пройти аккаунт SFON и выгрузить всё, что выгружается в Excel (продажи — окнами по 31 дню, приёмки, склад в себестоимости, долги, контрагенты). Проверить, есть ли IMEI и себестоимость в выгрузке склада.
2. **Справочники**: модели, цвета, память — из Open API SFON (ключ выдаёт SFON владельцу; хранится только на сервере) или из выгрузки.
3. **Контрагенты и долги**: импорт Excel с предпросмотром; открытые долги — начальными остатками с подписью владельца.
4. **Остатки по IMEI**: если в выгрузке есть IMEI и себестоимость — импорт; **в любом случае** — сплошная ревизия сканом в каждом филиале в день переноса (это и проверка выгрузки).
5. **История продаж**: импорт как справочная информация (для гарантии и возвратов по старым чекам) без проводок по складу.
6. **Параллельная работа 2 недели**: продажи в обеих системах, ежедневная сверка остатков и кассы.
7. **Переключение** в начале месяца после сверки; SFON — только чтение ещё 1–3 месяца для старых гарантий.
8. **Откат**: до переключения SFON остаётся главной системой; сбой — продолжаем в SFON.

|---|---|---|---|
| Двойная продажа IMEI из-за ошибки в своём ядре | средняя | высокое | ограничения в БД, тесты конкурентности в CI, одна функция продажи |

## 6. Первые 10 задач

1. **Доступ и данные SFON** (с владельцем): демонстрация аккаунта Prime Mobile, выгрузка всех отчётов, список реально используемых функций. *Готово, когда*: таблица «функция → используется да/нет» и образцы выгрузок.
2. **Каркас проекта**: Laravel 13 + Filament 5 + PostgreSQL 16 + Redis, CI (тесты, Pint, Larastan), контейнеры для локальной разработки. *Готово*: пустая админка разворачивается одной командой, CI зелёный.
3. **Мультиарендность**: `tenants`, `branches`, `tenant_id` + RLS-политики, промежуточный слой установки арендатора, тест «A не видит и не меняет B» по каждому маршруту.
4. **Роли и права**: владелец/админ/продавец, привязка к филиалу, право «видеть себестоимость», обязательная 2FA для владельца.
5. **Каталог**: тип → семейство → модель, цвет/память/RAM, аксессуары.
6. **Ядро единицы IMEI**: таблица `device_units`, уникальные индексы IMEI1/IMEI2, Luhn, журнал `stock_moves` только на добавление.
7. **Функция продажи единицы** под `FOR UPDATE` + **тест конкурентности** (2 процесса × 50 прогонов = 0 двойных) — первым делом, до экранов.
8. **Приёмка партии**: скан IMEI, себестоимость, поставщик, новый/б/у.
9. **Касса MVP**: скан → корзина → оплата (наличные/безнал/смешанная) → чек PDF, Idempotency-Key.
10. **Импорт Excel** контрагентов и остатков с предпросмотром — для пробного переноса данных Prime Mobile на копии.

## 7. Чего не хватило для полного заключения

- Доступа к аккаунту SFON Prime Mobile (состав выгрузок, реальное использование функций).
- Запуска Inventoros (нужен PHP 8.4 — установка из стороннего репозитория в этой среде запрещена) и ERPNext v16 (проверен v15).
- Цен хостинга и ОФД-операторов в Казахстане — их нужно запросить.
- Проверки сценариев «изоляция компаний», «возврат», «перемещение» на ERPNext (время ушло на установку в обход ограничений среды).
