**Вывод для Prime Mobile OS.** Нужна своя мультиарендность «по умолчанию закрыто»: `tenant_id NOT NULL` во всех таблицах бизнеса, **PostgreSQL Row Level Security** как второй рубеж (сессионная переменная `app.tenant_id`, политика на каждую таблицу), никаких общих строк с `NULL`, отдельная роль БД для фоновых задач с явным арендатором. ## 4. Обязательные требования к Prime Mobile OS (вывод из провалов)

1. **IMEI — отдельная сущность единицы** (`device_units`): `imei1`, `imei2`, `serial`, статус, филиал, себестоимость. Индексы `UNIQUE (tenant_id, imei1)`, `UNIQUE (tenant_id, imei2) WHERE imei2 IS NOT NULL`, проверка «IMEI2 не совпадает с чьим-то IMEI1» триггером; проверка формата 15 цифр + контрольная цифра Luhn (с явным флагом «серийный номер не-IMEI»).
2. **Продажа единицы — один SQL-шаг под блокировкой**: `SELECT … FROM device_units WHERE id=? AND tenant_id=? AND branch_id=? AND status='in_stock' FOR UPDATE` → если нет строки — отказ **до** приёма оплаты; затем смена статуса и запись в журнал движения в той же транзакции. Ни одного пути продажи (касса, API, импорт, офлайн-синхронизация) в обход этой функции.
3. **Ограничение-предохранитель в базе**: `CHECK (qty >= 0)` на остатках аксессуаров; частичный уникальный индекс «у единицы одна активная продажа» (`UNIQUE (unit_id) WHERE status = 'sold'` в строках продажи) — даже ошибка в коде не даст двойную продажу.
4. **Идемпотентность**: каждый изменяющий запрос (в том числе офлайн-касса) несёт `Idempotency-Key`; таблица ключей с уникальностью `(tenant_id, key)`, повтор возвращает сохранённый ответ.
5. **Журнал только на добавление** (`stock_moves`, `audit_log`): правок нет, отмена — обратной записью.
6. **Мультиарендность**: см. §2 (RLS + тесты изоляции в CI).
7. **Себестоимость единицы** фиксируется при приходе и не меняется задним числом без записи-корректировки (право «видеть себестоимость» — отдельное, продавцу по умолчанию не видно).
8. **Безопасность**: обязательная 2FA для владельца и админа; токены API с областями и сроком; ограничение частоты на все маршруты; приватное хранилище файлов (S3-совместимое) с подписанными ссылками; доверие прокси только к адресам балансировщика; шифрование секретов интеграций (ОФД, Kaspi) ключом из хранилища секретов; ежедневные резервные копии PostgreSQL с проверкой восстановления (PITR).
9. **Персональные данные (Закон РК «О персональных данных и их защите»)**: хранение данных граждан РК на серверах в Казахстане (требование локализации) — это ограничивает выбор хостинга (отчёт 06).
10. **Тесты конкурентности в CI**: два процесса продают один IMEI × 50 прогонов — должно быть 0 двойных; то же для перемещения и возврата.
