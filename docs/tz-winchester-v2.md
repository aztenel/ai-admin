# ТЗ: Winchester — два номера, сервис через бота, маркетинг с официального номера

Зафиксировано 18.10.2026 со слов владельца. Причина: с 1.10.2026 Meta берёт плату за ответы в 24-часовом окне сверх
1 000 в месяц на номер (≈ 8 ₸ за сообщение) и за шаблоны Utility внутри окна. Бот на официальном номере стал бы
дорогим и непредсказуемым по расходам. Дополняет `docs/winchester-crm.md` и `docs/handoff.md`.

## 1. Схема

| | Основной номер +7 700 505 05 03 | Второй номер (бот) |
|---|---|---|
| Подключение | Wazzapo (официальный API Meta, режим «сосуществование») | Green-API (неофициальный, по QR) |
| Кто отвечает | администратор с телефона или из пульта; **бот выключен** (`waOff`) | ИИ-бот 24/7 |
| Что идёт | маркетинговые рассылки по базе Altegio (шаблоны Meta), сложные вопросы | консультация, окна Altegio, запись/перенос/отмена своих записей, напоминания, просьба об отзыве |
| Расходы | шаблоны Marketing (платно за каждое), ответы сверх 1 000/мес | только абонплата Green-API |

Оба номера видны в одном пульте у бота `winchester`: `/api/inbox/list` берёт каналы `wa` и `ga`, если у клиента задан
Green-API (`src/controllers/inbox.js`). Бонусы, подтверждение записи и напоминание за 1 час уже присылает **сам Altegio**
(ссылки openhc.kz) — бот их не дублирует и бонусы не начисляет (сотрудник-бот в Altegio — только просмотр).

## 2. Второй номер на Green-API — правила безопасности (обязательные)

Номер уже был в живой переписке через Green-API, потом на WABA, потом WABA отключили.

1. Перед подключением: номер **удалён** из WhatsApp Manager (не просто отключён), WhatsApp Business на телефоне работает,
   в «Связанных устройствах» нет лишнего. Иначе QR Green-API не привяжется или будет конфликт.
2. Бот **только отвечает** на входящие. Первым не пишет — кроме напоминаний и отзыва по своей записи.
3. Сервисные сообщения (напоминание о записи, просьба об отзыве) — только по записям, которые клиент сделал в этом чате
   (так уже устроено). Правило «только 24 часа» и молчание на «спасибо» пробовали 18.10 и убрали: бот становился неудобным,
   а риск блокировки от ответов и напоминаний своим клиентам мал.
4. Рассылки через Green-API для Winchester **запрещены** (страница `/broadcast` и API должны отказывать для канала `ga`).
5. Основной номер **никогда** не подключается к Green-API.

**Сделано 18.10.2026 (на заглушках, `test/unit/two-numbers.test.mjs`):** флаги `gaOff`, `gaNoBroadcast` у Winchester, `BOT_GA_WINCHESTER = 1` включает бота на этом номере (официальный номер остаётся выключенным), подписи номеров в пульте.

Переменные (Cloudflare → Previews, потом Production): `GA_ID_WINCHESTER` (Text), `GA_TOKEN_WINCHESTER` (Secret),
`GA_URL_WINCHESTER` (Text). Вебхук ставится кнопкой «Настроить Green-API» на `/launch?c=winchester`.

## 3. Как перевести клиентов на номер бота

- Приветственное сообщение в приложении WhatsApp Business основного номера: «Записаться 24/7 — наш AI-администратор:
  wa.me/<номер бота>». Платно ли оно в режиме сосуществования — уточнить у Wazzapo.
- winchester.kz (репозиторий `aztenel/landing`): кнопки «Записаться» → номер бота.
- Instagram, 2ГИС: номер бота как «WhatsApp для записи», основной — «Телефон».
- Маркетинговый шаблон с основного номера — с кнопкой-ссылкой `https://wa.me/<номер бота>?text=Хочу записаться`:
  ответ клиента уходит боту (бесплатно), а не администратору на платный номер.

## 4. Маркетинг с основного номера: база Altegio

### 4.1. Откуда данные
- Записи за последние 90 дней (по фильтру Altegio сейчас ≈ **1 120** клиентов) — журнал записей Altegio ключом
  пользователя (`ALTEGIO_USER_WINCHESTER`, сотрудник-бот «просмотр»), постранично. Учитывать только состоявшиеся визиты
  (клиент пришёл), отменённые и неявки — нет.
- По каждому клиенту: телефон, имя, дата последнего визита, число визитов за период, мастер, услуга последнего визита,
  есть ли будущая запись.
- Позже (по желанию): вся база 18 891 через поиск клиентов Altegio (визиты, сумма, первый визит).
- Снимок обновляется ночью фоновой задачей (только на боевом сайте), хранится в KV по ключу `crm:winchester:*`.
  Номера — только в хранилище; в журналы сервера — через `logSafe`.
- Проверка вживую: число клиентов в снимке ≈ 1 120 (как в фильтре Altegio).

### 4.2. Сегменты (кнопки с числами)
| Сегмент | Правило |
|---|---|
| Пора на стрижку | последний визит 21–35 дней назад, нет будущей записи |
| Давно не были | 36–60 дней |
| Уходят | 61–90 дней |
| Новые | 1 визит за период |
| Постоянные | 3+ визита за период |
| По мастеру | последний визит у выбранного мастера |
Всегда исключать: «стоп» (`optout:`), будущую запись, визит меньше 14 дней назад, кому уже писали маркетинг за 14 дней.

**Сделано 19.10.2026 (на заглушках, `test/unit/crm.test.mjs`; вживую не проверено):** снимок за 90 дней назад и 60 вперёд
(`services/crm/snapshot.js`, ключ `crm:winchester:snap`) — ночью в 04:00 на боевом сайте и кнопкой владельца
`POST /api/crm/refresh` (на черновике `dev` — только кнопкой); сегменты и исключения §4.2 (`services/crm/segments.js`);
`GET /api/crm/segments`, `GET /api/crm/list` (по 50, номера маской). Визит — прошедшая запись, не удалена и не «не пришёл»
(`attendance`/`visit_attendance` = -1); какие отметки ставят администраторы Winchester — смотреть распределение `att` в ответе
`/api/crm/segments` после первого обновления. Отметки «писали маркетинг» (`bcm:<клиент>:<день>`) ставит отправка шаблонов Meta/Wazzapo
(`bcTick`, раз за порцию), сегменты не берут таких 14 дней.

### 4.3. Автосценарий «Пора на стрижку» (главный)
Каждый день в 11:00 бот берёт клиентов, у которых **ровно N дней** (по умолчанию 28) с последнего визита и нет будущей
записи, и отправляет один маркетинговый шаблон. Это ≈ 10–15 сообщений в день вместо разовой рассылки на 1 120 —
дёшево, вовремя и без жалоб. Дневной предел (по умолчанию 20), выключатель, выбор шаблона — в пульте.

**Сделано 19.10.2026 (на заглушках, `test/unit/crm-broadcast.test.mjs`; вживую не проверено — шаблон не одобрен):** `services/crm/auto.js`.
Настройки `bcauto:winchester` = `{ on: false, days: 28, tpl, lang: "ru", cap: 20, from: 11, to: 20, text }` — по умолчанию **выключен**;
`GET /api/bc/auto?c=` (видят владелец и сотрудник; `today` — кому написал бы сегодня), `POST /api/bc/auto` — только владелец.
Каждый день в 11:00–11:09 по Астане (только боевой сайт: у черновиков фоновой задачи нет) — клиенты ровно N дней с визита,
те же исключения §4.2, не больше предела (постоянные первыми), подстановка `{{1}}` = имя; рассылка сразу запускается и видна
на странице рассылок («Пора на стрижку · ДД.ММ», `by: "auto"`). День пропускается с сообщением в Telegram: качество номера
жёлтое/красное или сегодня не проверено (проверка в 10:00 не удалась), сигнал Meta «остановиться», номер не подключён, база старше
36 часов, сбой хранилища. Часы отправки — «до» позже 11:00. Рассылка автосценария идёт только в день создания: не успела (предел
номера занят другими рассылками) — назавтра останавливается с сообщением в Telegram, вместе с новой не уходит.

**Исправлено после проверки тремя агентами (19.10.2026, на заглушках):** исключения §4.2 проверяются ещё раз перед каждой
порцией отправки по свежему снимку и отметкам «писали маркетинг» — две рассылки по пересекающимся сегментам или ручная и
автосценарий пишут человеку один шаблон, кто записался после создания рассылки — не получит; база старше 3 дней — рассылка
встаёт на паузу и не запускается. Номера в отчёте «не дошло» (`/api/bc/get?bad=1`) у рассылки по базе — только маской.
Вторая проверка исправлений: снимок помнит и записанных, чей последний визит уже старше 90 дней (рассылка «Уходят» им не напишет);
проверка номера в 10:00 записывается и без Telegram, а если Meta/Wazzapo не сообщили качество при включённом автосценарии — строка
в сигнале (поле качества у Wazzapo вживую не проверено: если его нет, автосценарий будет пропускать дни — пульт покажет причину);
«Продолжить» у вчерашней рассылки автосценария только снимает сигнал Meta, сама рассылка не уходит.
Третья проверка (трое проверяющих, каждую находку перепроверили двое; 11 подтверждены, все низкой важности — исправлены):
в 11:00 автосценарий читает из Altegio свежие записи с сегодняшнего дня (записавшийся утром не получит приглашение); проверка номера
не удалась в 10:00 — ещё попытка в 11:00; маркетинг — только при зелёном качестве; выключили автосценарий — рассылка дня
останавливается; рассылка дня, которая сегодня не успевает, останавливается сразу (а не в полночь); сигнал Meta без остановленной
рассылки владелец снимает кнопкой «Снять сигнал Meta» на странице рассылок; оборванная порция отправки помечается «писали маркетинг»;
номер из текста ошибки Meta в заметке и Telegram скрыт; очередь отправки не записалась — рассылка на паузе с объяснением.
Осталось как было: смена шаблона, предела и часов автосценария действует со следующего дня; оборванная порция не попадает в счётчик
предела номера за сутки (старое поведение).
**Перед включением на боевом сайте — платный тариф Workers:** сборка снимка Winchester занимает ≈ 60–170 мс процессора,
а бесплатный тариф даёт 10 мс на запуск (обрыв без сообщения об ошибке).

### 4.4. Ограничения Meta (не нарушать)
- Только одобренные шаблоны категории Marketing, в каждом — «стоп». Подстановка `{{1}}` = имя.
- Часы отправки 11:00–20:00 по Астане. Порциями; на жёлтом качестве номера — автоматическая пауза (`qualityRun`).
- Фоновые задачи работают только на боевом сайте → нужна выкладка (`main`) по слову «выкладывай».

## 5. Пульт: раздел «Рассылки» (новый пульт `apps/pult`, ветка `pult-v2`; сервер — мы)

Права: запускать — владелец и управляющий; администраторы — только смотрят отчёты.

1. **Обзор:** качество номера (зелёный/жёлтый/красный), предел Meta, отправлено сегодня и за месяц, расход за месяц
   (оценка: число × цена шаблона), кнопка «Пауза всего».
2. **Сегменты:** карточки §4.2 с числами; фильтры (дни с визита — от/до, мастер, услуга, число визитов); список людей
   (имя, последний визит, мастер); кнопка «Создать рассылку».
3. **Мастер рассылки:** сегмент → шаблон (только одобренные Marketing) → предпросмотр на телефоне с подставленным именем
   → **оценка стоимости** → пробная отправка себе → когда (сейчас / дата и время) и сколько в день → подтверждение
   (больше 100 получателей — повторное подтверждение с суммой).
4. **Автосценарии:** «Пора на стрижку» (§4.3: вкл/выкл, N дней, шаблон, предел в день); позже — «День рождения»,
   «Вернуть ушедших» раз в месяц.
5. **История:** по каждой рассылке — отправлено, доставлено, прочитано, ошибки (причины простыми словами), ответили,
   «стоп», **записались в течение 7 дней** (сверка с журналом Altegio), стоимость.
6. **Шаблоны:** список из Meta со статусом (одобрен / на проверке / отклонён) и категорией.
7. **Стоп-лист:** кто отказался и когда.

### 5.1. API для пульта (сделать на сервере)
| Метод | Что |
|---|---|
| `GET /api/crm/segments?c=` | сегменты с числами |
| `GET /api/crm/list?c=&seg=&from=&to=&staff=` | люди сегмента (постранично) |
| `GET /api/bc/templates?c=` | шаблоны Meta и статусы |
| `POST /api/bc?c=` | создать рассылку из сегмента (шаблон, когда, предел в день) |
| `POST /api/bc/test?c=` | пробная отправка на номер владельца |
| `POST /api/bc/:id/pause`, `/resume` | пауза / продолжить |
| `GET /api/bc?c=`, `GET /api/bc/:id/report?c=` | история и отчёт |
| `GET/POST /api/bc/auto?c=` | автосценарии |
| `GET /api/bc/optouts?c=` | стоп-лист |
Ответы — `jsonP` (no-store), изменения — проверка источника (`sameOrigin`), права — `canSee` + роль. Контракт маршрутов
и тесты обновить.

**Сделано 19.10.2026 (на заглушках):** `GET /api/crm/segments`, `GET /api/crm/list`, `POST /api/crm/refresh` (только владелец),
`GET/POST /api/bc/auto`. Создать рассылку из сегмента — существующие `POST /api/bc/check` и `POST /api/bc/create` с полем
`segment` (`"pora"` или `{ id, from, to, staff }`): получателей строит сервер из снимка, браузер номеров не присылает и полных
не получает (только маской); только шаблоном Meta; база старше 3 дней — отказ. Пауза/продолжить/история/пробная отправка — прежние
`/api/bc/act`, `/api/bc/list`, `/api/bc/get`, `/api/bc/test`. Нет: `GET /api/bc/templates` (шаблоны из Meta), `GET /api/bc/optouts`,
отчёт «записались за 7 дней», оценка стоимости.

### 5.2. Сделано в новом пульте 19.10.2026 (на заглушках, вживую не проверено)

**Решение владельца 19.10.2026** (главнее пунктов 1–7 выше): старая страница `/broadcast` не нужна — всё в новом пульте; два вида
рассылок — две вкладки раздела «Рассылки»:
- **«Маркетинг · основной номер»** — только шаблоны Meta: обзор номера (качество, предел Meta, отправлено за 24 часа, отказались,
  недоставленные сегодня; сигнал Meta — красной плашкой, «Снять сигнал Meta» — только владелец); база клиентов (клиентов за 90 дней,
  доступно, когда обновлена, скрытые номера, «не пишем» по причинам, отметки визитов; плитки сегментов и мастера; люди сегмента —
  номера маской, отбор по дням с визита и мастеру; «Обновить базу» — только владелец); автосценарий «Пора на стрижку» (включить —
  только с шаблоном и с подтверждением «каждый день в 11:00»; настройки — владелец, сотрудник только видит); история (ход, почему
  пауза, «Не дошло — почему», Запустить / Продолжить / Пауза / Остановить / Удалить). Мастер «Новая рассылка» — **только основной
  номер**, выбора номера нет: сегмент базы или вставленный список → шаблон, язык, подстановки, текст → часы (11–20) и предел в сутки
  (95% предела Meta) → проверка сервером (получатели, примеры маской, предпросмотр пузырём WhatsApp, **оценка стоимости** — получатели
  × 27,3 ₸, «точная цена — в кабинете Meta») → пробная себе → согласие → создать / создать и запустить (больше 100 — второе
  подтверждение с суммой; сигнал Meta — вопрос сервера). Нет основного номера — вместо мастера фраза «Маркетинговые рассылки —
  только с основного номера WhatsApp (Meta). Он не подключён».
- **«Сервисные · номер бота»** — номер бота (на связи, вебхук) и что бот шлёт сам, без администраторов: накануне в 18:00, за 2 часа,
  просьба об отзыве через 3 часа. Пока только объяснение: очередь из `GET /api/bc/service` — следующей правкой. Рассылок текстом
  с номера бота пульт не создаёт.

Проверка: `cd apps/pult && npm run e2e:campaigns` — браузер на настоящем коде бота с заглушками (Winchester — владелец и сотрудник,
«Демо Дент» — рассылка списком), телефон и компьютер, светлая и тёмная тема; полных номеров базы на странице нет. **Не сделано**
(сервер не умеет): шаблоны из Meta со статусом, стоп-лист списком, доставлено / прочитано, «записались за 7 дней», отложенный запуск,
«Пауза всего», расход за месяц. Права по п. «администраторы только смотрят» не сделаны: сервер, как и раньше, даёт сотруднику создавать
и запускать рассылки. Пульт на сайт не выложен (`apps/pult/README.md`).
