# Ключи и данные клиентов: что делать

Для владельца. Простыми словами. Составлено 17.10.2026 (модуль 11 плана проверки).
Ключи вписываются **только** в панели Cloudflare (Workers → ai-admin → Settings → Variables and Secrets, тип Secret). В чат, письма, документы и GitHub — никогда.

## Сменить ключ владельца `LEADS_KEY`

Когда: ключ мог увидеть кто-то чужой, ушёл человек, который его знал.

1. Придумать новый длинный ключ (от 24 знаков, буквы и цифры).
2. Cloudflare → ai-admin → Settings → Variables and Secrets → `LEADS_KEY` → Edit → вставить → Deploy.
3. Если ключ нужен и черновику (`dev`) — то же в разделе Previews.

Что произойдёт: **все** открытые входы (владельца и сотрудников) закроются сразу, на всех телефонах и компьютерах. Владелец входит заново новым ключом. Ключи сотрудников остаются прежними — сотрудники просто входят ими ещё раз. Адреса `/diag?key=…` и `/api/selftest?key=…` — теперь с новым ключом.

## Сменить ключ сотрудника пульта

«Мои боты» → бизнес → «Ключ сотрудника» → выдать новый. Прежний ключ и все входы по нему перестают действовать сразу. Новый ключ передать сотруднику лично, не в общий чат.

## Сменить токен Green-API

1. Кабинет Green-API → инстанс → сменить токен (apiTokenInstance).
2. Cloudflare → `GA_TOKEN_<ID>` (например `GA_TOKEN_WINCHESTER`) → вставить новый → Deploy.
3. Страница «Проверка запуска» → «Настроить Green-API». **Обязательно:** пароль вебхука получается из токена, со старым адресом вебхука сообщения перестанут приниматься (сервер ответит 403). Green-API перезапустит инстанс — до 5 минут.
4. Написать боту с любого номера и убедиться, что он ответил.

## Сменить ключ Wazzapo

1. Кабинет Wazzapo → выпустить новый ключ API → Cloudflare `WA_TOKEN_<ID>` → Deploy.
2. Если меняли и секрет вебхука в Wazzapo — тот же новый секрет в `APP_SECRET_<ID>`. Без этого входящие сообщения отклоняются как неподписанные.
3. Проверить: написать боту, получить ответ; на странице `/diag` нет новой ошибки отправки.

## Сменить токен Telegram-бота

Telegram → @BotFather → `/revoke` → выбрать бота → новый токен в `TG_TOKEN` → Deploy. Чаты (`TG_CHAT`, `TG_CHAT_<ID>`) не меняются.

## Клиент просит удалить его данные

На странице `/privacy` обещано: «удалим в течение 10 дней».

1. Пульт → найти чат клиента → «⋯» → **«Удалить данные клиента»** (кнопка видна только владельцу) → подтвердить.
2. Удаляются: переписка, заявки с этим номером, отметка о согласии, напоминания, дневной предел записей.
3. Остаётся: отметка «стоп», если клиент просил не писать, — иначе бот и рассылки снова начнут ему писать.
4. Вручную, вне сервиса: запись клиента в Altegio (если он просит удалить и её), сообщения о нём в Telegram-чате, файлы Excel с рассылками у себя на компьютере. Списки рассылок в сервисе удаляются сами через 180 дней.
5. Ответить клиенту, что данные удалены.

Если чата уже нет в пульте (переписка хранится 7 дней), данных переписки тоже нет; заявки хранятся 30 дней и удаляются сами.

## Номера телефонов в журнале сервера

Номера клиентов в журнале Cloudflare (Logs) и на странице `/diag` показываются скрытыми: `+7 705 *** ** 01`. Если где-то увидите полный номер — сообщите разработчику.
