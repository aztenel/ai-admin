# Запуск Winchester на боевом сайте: база D1, выкладка, проверка, откат

Составлено 01.11.2026 по ветке `audit/winchester-handoff-2026-10-31` (PR №2, `62d23ef` и новее). Кому: владельцу — что решить и
что нажать; помощнику Claude — точные команды. Ничего из этого ещё не выполнялось на боевом сайте: всё, что отмечено «проверено»,
проверено на локальной копии и заглушках (раздел 1). Приёмка по сценариям — `docs/runbooks/winchester-acceptance.md`,
инструкция для Кайрата — `docs/winchester-kairat-handoff.md`.

## 0. Коротко

- **Что выкладываем:** ветку `dev` вместе с PR №2 (аудит, ревью, повторы Green-API) — в `main`, то есть на боевой сайт
  `https://ai-admin.azikonps4.workers.dev`. `main` целиком входит в `dev`, конфликтов нет.
- **Главное условие:** вместе с кодом подключить боевую базу D1 `ai-admin`. Без неё второй номер из пульта **не отправляет**
  («Отправка со второго номера не настроена…» — так задумано: без базы нет защиты от двойной отправки). Сегодня на боевом сайте
  второй номер отправляет по-старому, без базы, — поэтому выкладка без базы была бы шагом назад.
- **Порядок:** миграции и отметка базы → привязка `DB` в `main` → выкладка → проверки. Сначала база, потом код: если код выйдет
  раньше, пульт честно напишет «не настроена» (проверено), но администратор не сможет отвечать со второго номера из пульта.
- **Что не включается при запуске:** бот на обоих номерах, напоминания по журналу, рассылки со второго номера, настоящая запись с
  сайта (раздел 4, шаг 6).
- **Время:** 30–40 минут у компьютера (или в сессии Claude с подключением Cloudflare) и 15–20 минут проверки с телефона.

## 3. Решения владельца до запуска

1. **«Выкладывай»** — `dev` → `main` (боевой сайт).
2. **«Подключай D1»** — миграции на `ai-admin` и привязка `DB`.
3. **Основной номер в пульте.** Да — Wazzapo остаётся подключённым, вебхук Wazzapo ведёт на боевой адрес
   `https://ai-admin.azikonps4.workers.dev/wz/winchester` (сейчас, по `docs/handoff.md` §3, он вёл на черновик), переменные
   основного номера — в Production. Нет (решение 30.10) — основной номер отключается от API в приложении WhatsApp Business и
   работает только на телефоне администратора; в пульте — один второй номер.
4. **Два разрешённых номера для живой проверки** (свой и, например, номер Кайрата или администратора) — с их согласия.

## 4. Порядок запуска

### Шаг 1. Слить PR №2 в `dev`

Владелец сливает PR №2 в GitHub (или говорит помощнику «сливай»). Черновик `dev` обновится сам; боевой сайт не меняется.
По желанию, с разрешения владельца, — миграция 0005 на базу черновиков (иначе на черновике отправка со второго номера тоже будет
«не настроена», но черновик и так никому не пишет):

```sh
npx wrangler d1 migrations apply PREVIEW_DB --remote --config wrangler.preview-migrations.jsonc
```

### Шаг 2. Точка восстановления боевой базы

```sh
npx wrangler d1 time-travel info ai-admin
```

Записать закладку (bookmark) в заметки владельца — не в репозиторий. Помощник через подключение Cloudflare закладку сделать не
может: если миграции выполняет он (шаг 3, вариант Б), точкой служит пустая база — её можно пересоздать.

### Шаг 3. Миграции и отметка на боевой базе `ai-admin`

**Вариант А — компьютер с Node.js, вход `npx wrangler login`** (стандартный путь, `wrangler` сам ведёт учёт миграций):

```sh
git apply docs/runbooks/winchester-go-live-d1.patch   # привязка DB → ai-admin в рабочей копии (её же потом выкладываем)
npx wrangler d1 migrations apply DB --remote
npx wrangler d1 execute DB --remote --command "INSERT INTO meta (k, v) VALUES ('stage', 'production') ON CONFLICT(k) DO NOTHING"
npx wrangler d1 execute DB --remote --command "SELECT (SELECT v FROM meta WHERE k = 'stage') AS stage, (SELECT count(*) FROM d1_migrations) AS migrations, (SELECT count(*) FROM sqlite_master WHERE type = 'table' AND name = 'send_claims') AS send_claims"
```

Ожидаем: `stage = production`, `migrations = 5`, `send_claims = 1`. Миграции применяются по одной: 0001_messaging.sql,
0002_contacts_sync.sql, 0003_consent_evidence.sql, 0004_demo_source.sql, 0005_send_claims.sql.

**Вариант Б — без компьютера: помощник Claude через подключение Cloudflare** (так обновляли базу черновиков 31.10). По слову
«подключай D1» помощник выполняет на базе `ai-admin` (id `ea1610ed-d342-41ca-8170-40ffe81feb41`, не путать с `ai-admin-dev`):

1. `CREATE TABLE IF NOT EXISTS d1_migrations(id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT UNIQUE, applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL)`
2. Для каждого файла по порядку — 0001_messaging.sql, 0002_contacts_sync.sql, 0003_consent_evidence.sql,
   0004_demo_source.sql, 0005_send_claims.sql: текст файла целиком (строки-комментарии `--` можно убрать — так выполняли для базы
   черновиков), затем `INSERT INTO d1_migrations (name) VALUES ('<имя файла>')`. Ошибка на файле — остановиться: учёт показывает,
   какие уже применены.
3. `INSERT INTO meta (k, v) VALUES ('stage', 'production') ON CONFLICT(k) DO NOTHING`
4. Та же проверка `SELECT`, что в варианте А.

Повтор команды отметки ничего не меняет; если отметка оказалась не та (`preview`), команда её не перезапишет — это покажет
проверка, и базу нужно разбирать вручную.

### Шаг 4. Привязка `DB` и выкладка

1. На `dev` (после шага 1): `git apply docs/runbooks/winchester-go-live-d1.patch` — правка добавляет в `wrangler.jsonc` боевую
   привязку `DB → ai-admin` и меняет одну проверку схемы (раньше она требовала, чтобы у боевого сайта базы не было).
   `npm test` — зелёный. Коммит «Боевая база D1 ai-admin подключена», push в `dev`.
2. Проверки GitHub (Node 20/22/24 и пробная сборка) — зелёные.
3. PR `dev` → `main`, слияние — это и есть выкладка (Cloudflare Workers Builds собирает `main` сам, 2–5 минут).

Правка не применится (`git apply` откажет), если с 01.11 менялись `wrangler.jsonc` или `test/unit/d1-schema.test.mjs`. Тогда та же
правка руками: в `wrangler.jsonc` после `kv_namespaces` верхнего уровня —

```jsonc
"d1_databases": [
  { "binding": "DB", "database_name": "ai-admin", "database_id": "ea1610ed-d342-41ca-8170-40ffe81feb41", "migrations_dir": "migrations" }
],
```

а в `test/unit/d1-schema.test.mjs` вместо «у боевого сайта D1 нет» — проверка, что у боевого сайта `ai-admin`, а у черновиков
другая база (готовый текст — в файле правки).

### Шаг 5. Проверки сразу после выкладки (10–15 минут)

| Что | Где | Ожидаем |
|---|---|---|
| Сборка | Cloudflare → Workers & Pages → ai-admin → Deployments | Новая версия, привязки `KV` и `DB` |
| База | `/diag/storage` (вход владельца) | «Этот адрес: боевой сайт — KV aiai»; «отметка базы: production — совпадает ✅»; «миграции: 0001_messaging.sql, …, 0005_send_claims.sql; таблиц: 23» |
| Второй номер | `/launch?c=winchester` | «WhatsApp (Green-API)» — номер привязан; «Green-API: вебхук» — «настроен на ai-admin.azikonps4.workers.dev» |
| Вебхук не тот | там же: «не настроен» или «ведёт на другой адрес (…)» | Решение владельца: кнопка «Настроить Green-API» впишет адрес боевого сайта и включит уведомления; инстанс перезапустится, до 5 минут |
| Сайт и бот | `/`, `/?c=barber`, `/privacy`, автотест `/api/selftest?key=…&i=1` | Открываются, автотест проходит (`CLAUDE.md` §5.5) |
| Пульт | `/app/` с телефона, вход ключом | Чаты второго номера; под полем ввода «Ответ уйдёт со второго номера»; плашки «не настроена» нет |

### Шаг 6. Что остаётся выключенным

- Бот на втором номере (`gaOff` в коде) и на основном (`waOff`) — переменные `BOT_GA_WINCHESTER`, `BOT_WA_WINCHESTER` не ставить.
- Рассылки со второго номера — запрещены в коде (`gaNoBroadcast`); черновик и одобрение — можно, запуск — нет.
- Напоминания и отзыв по журналу — `REMIND_GA_WINCHESTER` не ставить до «отправляй» Кайрата и одобренных текстов.
- Настоящая запись с сайта — `SITE_BOOKING_WINCHESTER` не ставить в `1` до живой проверки в режиме `dry` и слова Кайрата.
- Фоновая загрузка журнала в базу контактов — `MSG_V2_WINCHESTER` не ставить.

## 5. Откат

1. **Код.** Cloudflare → Workers & Pages → ai-admin → Deployments → у предыдущей версии «⋯» → Rollback
   (или `npx wrangler rollback <id версии>`). Действует сразу. У прежней версии нет привязки `DB`: сайт работает, как до выкладки,
   второй номер из пульта отправляет по-старому.
2. **GitHub.** Revert коммита выкладки в `main` — иначе следующая сборка `main` вернёт новую версию.
3. **База D1.** Схему не откатываем: прежний код базу не читает, новые таблицы ничему не мешают. Данные (отметки отправок,
   события) остаются и пригодятся при повторном запуске.
4. **Если испорчены данные базы:** `npx wrangler d1 time-travel restore ai-admin --bookmark=<закладка шага 2>` — база целиком
   возвращается к закладке, всё записанное позже пропадает (Time Travel хранит 30 дней на платном тарифе).
5. **KV.** Новая версия только добавляет ключи (подписи линий, push, тексты сервисных сообщений); прежняя их не читает. Удалять
   ничего не нужно.
6. **Вебхук Green-API** ведёт на тот же боевой адрес — при откате его не трогаем.

## 6. Безопасная живая проба на отдельном тестовом Worker (по желанию)

Когда: проверить второй номер живьём **до** выкладки, не трогая рабочий номер Winchester и боевой сайт. Нужен отдельный инстанс
Green-API с тестовым номером (не рабочим) и решение владельца создать ресурсы в Cloudflare.

1. Создать KV `ai-admin-test` и D1 `ai-admin-test` (панель, `wrangler` или помощник через подключение Cloudflare).
2. На базе `ai-admin-test` — шаг 3 этой инструкции (миграции и отметка `production`).
3. Файл `wrangler.test.jsonc` (не в репозиторий; проверен пробной сборкой 01.11):

   ```jsonc
   {
     "name": "ai-admin-test",
     "main": "worker.js",
     "compatibility_date": "2026-09-28",
     "keep_vars": true,
     "workers_dev": true,
     "kv_namespaces": [{ "binding": "KV", "id": "<id KV ai-admin-test>" }],
     "d1_databases": [{ "binding": "DB", "database_name": "ai-admin-test", "database_id": "<id D1 ai-admin-test>", "migrations_dir": "migrations" }],
     "previews": {}
   }
   ```

   Без `triggers`: у тестового Worker нет фоновой задачи — ни рассылок, ни напоминаний, ни сводок.
4. Секреты тестового Worker: свой `LEADS_KEY`; `GA_ID_WINCHESTER`, `GA_TOKEN_WINCHESTER`, `GA_URL_WINCHESTER` — **тестового**
   инстанса; по желанию `ALTEGIO_PARTNER` и `ALTEGIO_USER_WINCHESTER` (журнал только читается: карточка записи и свободное время).
   `TG_*` — не задавать или тестовый чат.
5. `npx wrangler deploy --config wrangler.test.jsonc` → `https://ai-admin-test.azikonps4.workers.dev`.
6. `/launch?c=winchester` на тестовом адресе → «Настроить Green-API»: вебхук тестового инстанса ведёт на тестовый Worker. Рабочий
   инстанс и боевой сайт не затрагиваются.
7. Живая проверка — `docs/runbooks/winchester-acceptance.md`, раздел 3, на тестовом адресе.
8. После проверки удалить Worker, KV, D1 и тестовый инстанс.

Тестовый Worker знает настройки Winchester из кода (локация Altegio): с ключом журнала он читает настоящий журнал, но ничего в
Altegio не пишет — бот выключен, запись с сайта в режиме `dry`, из пульта записывать нельзя.
