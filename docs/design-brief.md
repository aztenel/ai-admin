# ТЗ: единая админ-панель («Кабинет») — дизайн и удобство

Для дизайнера и разработчика, который помогает с видом служебных страниц. Составлено 17.10.2026.
Сначала прочитай `CLAUDE.md` (разделы 0, 2.4, 5.4, 5.5) — там правила репозитория.
Как должно выглядеть — макет `docs/design-mockup.html` (открыть в браузере; это образец вида, не код страниц).

## 1. Зачем

Владелец работает с телефона и не технарь. Служебные страницы сейчас разрознены: у каждой своя шапка, переходы — набором
адреса вручную (`/launch?c=winchester`), часть страниц — простой текст. Нужно сделать из них одну понятную панель
в том же стиле, что и пульт чатов (`/inbox`), который уже переделан под мессенджер.

## 2. Что есть сейчас

| Адрес | Что это | Где код | Вид сейчас |
|---|---|---|---|
| `/login` | Вход по ключу | `src/controllers/auth.js` | HTML |
| `/studio` | «Мои боты»: список ботов, паспорт бота (форма), ключ сотрудника, удаление | `src/controllers/studio.js` | HTML, своя шапка |
| `/launch?c=<id>` | Проверка запуска: что подключено, чего не хватает, экзамен бота | `src/controllers/launch.js` | HTML, своя шапка |
| `/leads?c=<id>` | Заявки | `src/controllers/pages.js` | HTML |

| `/diag` | Диагностика: ключи, модели ИИ, расходы | `src/controllers/diag.js` | **простой текст** |
| `/altegio?c=<id>` | Проверка расписания Altegio | `src/controllers/altegio.js` | **простой текст** + форма |
| `/altegio/user` | Получить ключ журнала Altegio | `src/controllers/altegio.js` | HTML |

## 3. Что неудобно (найдено при работе владельца)

1. Нет общей навигации: из «Мои боты» не попасть в диагностику, из проверки запуска — в заявки; адреса приходится помнить.
2. Нужный бот задаётся в адресе (`?c=winchester`): легко ошибиться, на телефоне неудобно.
3. `/diag` и `/altegio` — сплошной текст с именами переменных Cloudflare; важное (ошибка, «не задан») теряется.
4. Служебные страницы (бирюзовая палитра `ADMIN_CSS`) выглядят иначе, чем пульт (системная палитра iOS).
5. Карточка бота в «Мои боты» — ряд из 5–7 ссылок без иерархии.
6. Проверка запуска — длинный список; непонятно, что делать первым.

## 4. Что сделать

### 4.1. Каркас «Кабинета» (общий для всех служебных страниц)
- **Шапка** с переключателем бота (как в пульте: кружок с буквой + название + стрелка). Выбранный бот запоминается
  (`localStorage`, с запасным вариантом — `?c=` в адресе, он должен продолжать работать: на нём ссылки из Telegram).
- **Навигация**: телефон — нижняя панель (как в пульте), компьютер (≥ 900 px) — боковая колонка.
  Пункты: **Чаты** (`/inbox`), **Заявки**, **Рассылки**, **Проверка** (`/launch`), **Ещё** → Мои боты, Диагностика, Altegio, Автотест, Выйти.
  Сотрудник (не владелец) видит только Чаты и Заявки.
- Один общий кусок кода для шапки и навигации (функция в `src/lib/`, например `layout.js`), а не копия в каждом файле.

### 4.2. Стиль
- Те же токены, что в пульте (`pult/design.base.css`): цвета, шрифт `-apple-system, "SF Pro Text", …`, размеры 34/17/15/13,
  радиусы. Светлая и тёмная тема по системной.
- Телефон 390 px — главный экран. Поля по краям 16 px, без горизонтальной прокрутки, кнопки не меньше 44 × 44 px.
- Контраст текста ≥ 4.5 : 1. Состояние — не только цветом: «✓ подключено», «✕ нет ключа», «! проверьте».
- Слова — простые, по-русски, без жаргона. Имена переменных (`WA_TOKEN_WINCHESTER`) показывать мелко и только там,
  где владельцу нужно вписать их в Cloudflare.

### 4.3. Страницы
- **Мои боты**: карточка = название, ниша, 3 состояния (WhatsApp, Telegram, Altegio — зелёный/жёлтый/красный),
  одна главная кнопка «Открыть» (→ чаты бота) и меню «⋯» с остальным (паспорт, ключ сотрудника, удалить).
- **Проверка запуска**: сверху сводка «Готово 5 из 7»; ниже шаги по порядку, у каждого — что не так и одна кнопка «Как исправить».
- **Диагностика** и **Altegio**: переделать из текста в карточки (Ключи, WhatsApp, ИИ — модели и расходы за 7 дней, Altegio).
  Ответ `/diag` сейчас — `text/plain`; новая версия — HTML через `page()` (см. 5.2). Данные те же, что в `diag()`.
  **Не показывать начало ключей** (сейчас `/diag` выводит первые 4 символа `GEMINI_KEY`) — только «задан / не задан».
- **Заявки** и **Рассылки**: перенести в новый каркас, логику не менять.

## 5. Технические рамки (обязательно)

1. **Ветка**: работать в своей ветке от `dev` (например `design`), изменения — пулл-реквестом в `dev`. В `main` не отправлять:
   `main` — боевой сайт, выкладывается каждый коммит.
2. **Безопасность страниц**: страницы с данными отдаются только через `page()` из `src/lib/http.js` (заголовки `no-store`,
   `x-frame-options`, CSP). CSP: `default-src 'self'` — **никаких внешних шрифтов, CDN, картинок и скриптов**; всё своё,
   встроенное. Любой текст из данных — через экранирование (`esc`).
3. **Сборки нет**: служебные страницы — HTML-строки внутри `src/controllers/*.js`. Не добавлять фреймворки и пакеты
   (React, Tailwind, Vite) — их переезд запланирован отдельно (`REFACTORING.md`, фаза 4). Пакеты не из `package.json`
   проверка границ не пропустит.
4. **Не менять**: адреса страниц, `/api/*` (запросы и ответы), бизнес-логику в `src/services/**`. Дизайн — только
   разметка, стили и клиентский JS страниц.
5. **Пульт** (`pult/*`): правка — только исходники в `pult/`, затем `node tools/build-pult.mjs`; `pult.gen.js` руками не править.
6. **Тесты должны быть зелёными** до и после каждого изменения:
   - `npm test` (~1 800 проверок, ~1 мин), `npm run check` (типы и границы);
   - пульт: `PLAYWRIGHT_PATH=… node test/e2e.mjs <папка>` (см. `CLAUDE.md` §2.4);
   - контракт маршрутов (`test/contract/`) проверяет коды ответов, заголовки защиты и ключи JSON. Если ответ страницы
     изменился намеренно (например `/diag` стал HTML): `UPDATE=1 node test/contract/routes.mjs`, прочитать разницу в git
     и объяснить её в описании PR.
7. **Локальный запуск без ключей**: `node test/devserver.mjs` → открыть адрес из консоли, вход ключом `owner-key-123456`
   (это заглушка, не настоящий ключ). Все внешние сервисы — заглушки.
8. **Репозиторий публичный**: никаких ключей, токенов, настоящих номеров телефонов и имён клиентов — ни в коде, ни на снимках
   экрана в PR. Для примеров — вымышленные данные из демо.

## 6. Порядок работ и приёмка

Каждый этап — отдельный PR в `dev` со снимками: телефон 390 px и компьютер 1280 px, светлая и тёмная тема.

| Этап | Что | Готово, когда |
|---|---|---|
| 1 | Каркас: шапка, переключатель бота, навигация, общий стиль | Все служебные страницы открываются в каркасе, переход между ними — в 1 касание, `?c=` работает как раньше |
| 2 | «Мои боты» | Карточка: состояния + «Открыть» + «⋯»; паспорт бота сохраняется как раньше |
| 3 | Проверка запуска | Сводка «N из M», шаги по порядку, у каждого — что сделать |
| 4 | Диагностика и Altegio в HTML | Ни одного начала ключа на странице; ошибки видны первыми |
| 5 | Заявки и Рассылки в каркасе | Логика и ответы API без изменений |

Общие условия приёмки: `npm test` и `npm run check` зелёные; e2e пульта зелёный; нет внешних ресурсов
(в DevTools → Network только свой адрес); на телефоне нет горизонтальной прокрутки.

## 7. Не входит в эту работу

- Пульт чатов (`/inbox`) — уже переделан; только ссылки на него из навигации.
- Витрина `/` и `/privacy`.
- Переезд на Vite / Tailwind / Supabase (`REFACTORING.md`).
- Тексты ответов бота клиентам.
